# v224 Saved Search Notification Rollback and Audit-Log Hardening

V224_SAVED_SEARCH_NOTIFICATION_ROLLBACK_AUDIT_HARDENING

## Purpose

v224 adds rollback and audit-log hardening around the saved-search notification flow after the v223 operator observability checkpoint.

This checkpoint adds structured audit event payloads, deterministic audit fingerprints, read-only rollback planning, and an explicitly gated timestamp rollback helper.

## Rollback report contents

The read-only rollback report shows:

- Candidate saved searches in scope.
- Rollback candidate count.
- Untouched candidate count.
- Saved search id.
- Owner id.
- Recipient email.
- Current sent timestamp.
- Saved-search label.

## Audit-log hardening behavior

The audit event payload includes:

- Marker.
- Schema version.
- Action.
- Operator.
- Reason.
- Saved search id.
- Owner id.
- Recipient email.
- Saved-search label.
- Delivery result summary.
- Rollback result summary.
- Deterministic SHA-256 audit fingerprint.

## Safety behavior

The v224 rollback/audit path:

- Keeps rollback reports read-only.
- Does not deliver email.
- Does not call the explicit-send sender from the rollback report.
- Does not mutate timestamps from the rollback report.
- Requires explicit `execute_rollback=True` before timestamp rollback.
- Rolls back only `last_notification_sent_at`.
- Preserves `last_notification_checked_at`.
- Does not add scheduler auto-delivery.
- Does not add a background process.
- Does not change models.
- Does not create migrations.
- Does not change URLs, views, forms, or admin classes.
- Keeps the default command path non-delivery.
