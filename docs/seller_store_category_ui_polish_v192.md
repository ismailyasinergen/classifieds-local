# v192 Seller Store Category UI Polish

V192_SELLER_STORE_CATEGORY_UI_POLISH

## Purpose

v192 improves seller-store category display clarity while keeping the public browse category navigation and saved-search behavior untouched.

## Repair history

- Initial v192 assumed the seller-store directory template lived at `backend/accounts/templates/accounts/store_directory.html`; that path does not exist.
- Repair 1 correctly discovered the actual template as `backend/accounts/templates/accounts/seller_store_directory.html`, but host Python failed to write `/tmp/...` on Windows.
- Repair 2 patches the discovered real template path directly.

## What v192 changes

- Adds a seller-store directory category-state note when a category filter is active.
- Clarifies that the directory is showing stores with active listings in the selected category and related subcategories.
- Clarifies that search, sorting, location, and pagination stay connected to the category filter.
- Adds a small accessible note region with `role="note"` and an explicit `aria-label`.
- Keeps public listing browse navigation and saved-search templates unchanged.

## Scope boundaries

v192 intentionally does not change:

- Seller-store models.
- Seller-store views.
- Seller-store URLs.
- Public listing browse template behavior.
- SavedSearch models/views/templates.
- Category seed files.
- Category navigation Python utilities.
- Public category navigation partial.

## Guardrails

- No migrations should be generated by v192.
- backend/docs/ must not be recreated.
- Public browse templates must not receive v192 seller-store UI hooks.
- v188/v189/v190/v191 compatibility tests must remain green.
- Existing saved-search regression tests must remain green.
- Existing seller-store compatibility tests must remain green.
- Full regression must pass before commit/tag.
