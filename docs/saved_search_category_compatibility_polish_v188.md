# v188 Saved Search Category Compatibility Polish

V188_SAVED_SEARCH_CATEGORY_COMPATIBILITY_POLISH

## Purpose

v188 verifies that the v186/v187 category navigation and the public browse `category` query parameter remain compatible with existing saved search behavior.

## Repair notes

The initial v188 test was too brittle in three places:

- It referenced a non-existent `electronics-audio-speakers` slug.
- It used a public anonymous navigation assertion that duplicated v187 coverage and did not reliably render the category navigation marker for all browse states.
- It assumed the repeat saved-search state would always show the original POST form, while the application may correctly show an already-saved state instead.

Repair 2 keeps v188 as a compatibility-only checkpoint. It focuses on saved-search behavior and URL/category state instead of re-testing the public navigation mount already covered by v187.

## What v188 checks

- Category filter URLs preserve query/sort state and drop stale pagination.
- Authenticated saved-search browse state keeps category, query, and sort parameters.
- Authenticated saved-search creation preserves category-aware browse state.
- Repeating the same category-aware saved-search state does not create duplicates.
- Result-preview and post-create flows do not crash with category-aware queries.
- Browse pagination remains safe with category, search, and sort parameters together.

## Scope boundaries

v188 intentionally does not change:

- SavedSearch model fields.
- Saved search URLs.
- Saved search templates.
- Seller store behavior.
- Category seed files.
- Category navigation utility code.

## Guardrails

- No migrations should be generated by v188.
- backend/docs/ must not be recreated.
- Only the v188 test file and top-level v188 doc should be staged.
- Full regression must pass before commit/tag.
