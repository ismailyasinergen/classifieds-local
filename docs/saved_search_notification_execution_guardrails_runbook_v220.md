## Purpose

v220 defines execution guardrails and an operator runbook for saved-search notification emails after the v219 sending dry-run contract.

This checkpoint is audit-only. It does not add a sender, does not deliver email, and does not integrate email rendering into the scheduler.

## Execution guardrails

Any future saved-search email execution must follow these guardrails:

1. Dry-run first.
2. Explicit operator confirmation before real sending.
3. Owner-scoped candidate selection.
4. Opt-in-only candidate selection.
5. Disabled saved searches rejected before rendering or delivery.
6. Rendered preview available before delivery.
7. Delivery count visible before execution.
8. Recipient list visible before execution.
9. Batch size or limit required before execution.
10. No silent background delivery.
11. No timestamp mutation during preview.
12. Sent timestamp mutation only after confirmed delivery exists.
13. Checked timestamp mutation only when the scheduler path explicitly runs.
14. Rollback posture documented before any real-send checkpoint.
15. Full regression required before any sender commit.

## Operator runbook

### Preflight checks

Before a future execution checkpoint, an operator should confirm:

- Current git status is clean.
- Current checkpoint tag is correct.
- Django check passes.
- Makemigrations dry-run reports no changes.
- Category seed verification passes.
- Saved-search notification tests pass.
- Email renderer tests pass.
- Dry-run contract tests pass.
- `backend/docs/` is absent.
- Email backend behavior is understood for the local environment.

### Dry-run flow

A future operator dry-run should show:

- Number of candidate saved searches.
- Number of candidates excluded because notifications are disabled.
- Number of rendered previews.
- Recipient emails.
- Subject lines.
- Match counts.
- Whether real delivery is disabled.
- Whether timestamp mutation is disabled.

### Real-send gate for a later checkpoint

A later real-send checkpoint must require an explicit execute flag or equivalent operator confirmation.

The future real-send path must not be triggered by default.

The future real-send path must not be triggered by merely running tests, Django checks, migrations, or Docker startup.

### Rollback posture

Before any real-send checkpoint, rollback notes should include:

- How to disable execution.
- How to restore dry-run mode.
- How to identify sent notification rows.
- How to inspect timestamp changes.
- How to verify no unintended background worker is running.
- How to stop Docker services if an operator sees unexpected delivery behavior.
