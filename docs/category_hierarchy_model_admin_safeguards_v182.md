# v182 Category Hierarchy Model and Admin Safeguards

V182_CATEGORY_HIERARCHY_MODEL_ADMIN_SAFEGUARDS

## Purpose

v182 is the first real category-taxonomy checkpoint after the v181 transition audit.

v181 confirmed that category taxonomy is the next feature area and that the existing Category model already has a parent/self hierarchy relation. v182 therefore hardens the existing hierarchy instead of creating a new model.

## Scope

v182 adds:

- Model-level validation that rejects a category being its own parent.
- Model-level validation that rejects parent-chain cycles.
- Admin registration safeguards for hierarchy management.
- Admin search, parent filtering, slug prepopulation, and hierarchy-visible list display.
- Regression tests proving the hierarchy safeguards work.

## Non-goals

v182 does not:

- Create main categories.
- Create subcategories.
- Create sub-sub-categories.
- Seed category data.
- Change listing browse navigation.
- Change listing create/update UX.
- Change saved search behavior.
- Change seller store category tabs.

Those belong in later checkpoints.

## Recommended next checkpoints

- v183: category seed taxonomy planning or seed command/data fixture.
- v184: category navigation and listing filter integration.
- v185: saved search and seller store category compatibility polish.

## Guardrails

- No migrations should be generated by v182.
- `backend/docs/` must not be recreated.
- Full regression must pass before commit/tag.
