## What v216 verifies

v216 does not perform a destructive restore. It verifies that the repository contains the pieces required to rehearse a local restore safely:

- Docker Compose configuration is renderable.
- A git archive can be created into `/tmp`.
- A temporary restore tree can be extracted outside the repository.
- The temporary restore tree contains Docker, Compose, nginx, backend, migration, and docs prerequisites.
- `backend/docs/` is absent from the archived restore tree.
- A git bundle can be created and verified into `/tmp`.
- Temporary restore rehearsal artifacts are removed from `/tmp`.
- No restore/archive/bundle artifacts are written into the repository.
- Recent release checkpoint tests remain packaged.
- Category seed verification command remains available.
- Saved-search notification scheduler command remains available.
- v215 SellerStore admin action safeguards remain packaged.

## Non-destructive rehearsal steps

A human local restore rehearsal should use a copy of the archive or bundle, not the live working tree.

Recommended non-destructive order:

    git status --short
    docker compose config
    git archive --format=tar --output=/tmp/classifieds_local_restore_rehearsal.tar HEAD
    mkdir -p /tmp/classifieds_local_restore_rehearsal
    tar -xf /tmp/classifieds_local_restore_rehearsal.tar -C /tmp/classifieds_local_restore_rehearsal
    git bundle create /tmp/classifieds_local_restore_rehearsal.bundle HEAD
    git bundle verify /tmp/classifieds_local_restore_rehearsal.bundle

Inside a copied restore tree, the local verification sequence should remain:

    docker compose config
    docker compose up -d --build
    docker compose exec web python manage.py check
    docker compose exec web python manage.py makemigrations --check --dry-run
    docker compose exec web python manage.py verify_marketplace_category_seed --require-applied
    docker compose exec web python manage.py test -v 2
